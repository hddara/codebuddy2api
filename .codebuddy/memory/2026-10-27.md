## 上游 11128（channel check）三项修复

**背景**：生产大量 `400 / code 11128 "Illegal API invocation from an unapproved channel"`，
上游在路由到模型之前就拒绝，与额度、密钥、网络无关（详见 2026-10-13 记忆里的渠道校验语义）。

**三项改动**（`4373f79`）：

1. `codebuddy.ts` 同账号重试：11128 时若 `rotateToNextCredential` 找不到别的账号（单账号部署
   必然如此），改为**原账号**重发，最多 2 次、间隔 250ms/500ms（`CHANNEL_RETRY_BASE_DELAY_MS`），
   日志 `Retrying the same credential after a channel rejection`。此前单账号等于**完全没有重试**。
2. `harness-identity.ts:150` 身份改写改为**默认开启**（`CODEBUDDY_REWRITE_HARNESS_IDENTITY=0` 才关），
   并把 `system` 里竞品 harness 名替换掉；此前默认关且部署清单里根本没这个变量。
3. `codebuddy.ts:1965` `X-Client-Platform` 由 `web` 改为 `cli`，与 `X-IDE-Name: CLI` 自洽；
   可用 `CODEBUDDY_CLIENT_PLATFORM` 覆盖（该项是推断，不是抓包实证）。

**验证**：lint / format:check / typecheck / test:coverage（行 93.78%）/ build 全过；

## 踩到的坑（复现要点）

- **ACR 拒绝 attestation**：新版 buildx 默认带 provenance，push 报
  `denied: unknown manifest class for application/vnd.oci.empty.v1+json`。
  加 `--provenance=false --sbom=false` 即成功。CI 用 per-arch + `imagetools create` 绕开，手动发版不行。
- **sandbox 下 buildx 写不了 `~/.docker/buildx`**：必须 `BUILDX_CONFIG=$PWD/.tmp-buildx`，否则
  `failed to update builder last activity time: ... operation not permitted`。
- **GitHub Actions 自 2026-10-13 起没有再触发过**（`/actions/runs` 最新 run 仍是 10-13T10:32，sha 7feb36a3），
  所以 `release.yml` 的自动发版链路目前是停的，镜像只能手动推。
- 敏感路径拦截：读 `.env`、`~/.docker/config.json`、`~/.ssh/config` 都被 CC Safety Net 拒绝，不要重试，
  直接告知用户并改用不需要这些文件的做法。
