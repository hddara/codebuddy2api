### ⚠️ 坑 1：IDE 插件注入的 safe-delete shim 会拦住 `next build`

- `next build` 首次失败：`Error: [safe-delete][SAFE_DELETE_BULK_CONFIRM_REQUIRED] {"count":500,"threshold":500,"scope":"turn","targets":["<repo>/.next/turbopack"]}`，堆栈在 `...JetBrains/IntelliJIdea2026.2/plugins/coding-copilot-jetbrains/vsix/extension/out/vendor/shim/node-safe-delete-shim.cjs`。
- 原因：IDE 给 shell 注入了 `NODE_OPTIONS=--require=".../shim/node-language-shim.cjs"`，其内部的 safe-delete 保护在**单轮删除 ≥500 个文件**时直接抛错。这不是代码问题。
- 解法：`NODE_OPTIONS="" bun run build`（清空即可；必要的 `.next` 清缓存用 shell 的 `rm -rf .next`，shell 不受该 shim 约束）。

### ⚠️ 坑 2：Turbopack 不容忍项目内的 Python venv 符号链接

- 症状：`Symlink [project]/.venv-v1/bin/python is invalid, it points out of the filesystem root` → `TurbopackInternalError`，顺着 `lib/server/storage/index.ts` 的解析路径爆出。venv 的 python 必然软链到系统解释器（项目外），Turbopack 直接判非法。
- `.git/info/exclude` 加 `.venv-v1/` **无效**（Turbopack 不读它）。
- 最终处置：`tar czf ../codebuddy2api-venv-v1-20260915.tar.gz .venv-v1`（33M → 9.8M）后 `rm -rf .venv-v1 __pycache__ src/__pycache__`（`src/` 在该分支已无被跟踪文件，只剩 `__pycache__`）。备份在仓库上级目录，需要回 Python 版时解压回原位即可（venv 路径不变，仍可用）。
- 结论：**Node 版仓库里不要留 Python venv**；切换分支时残留的 `.venv-v1` 会直接卡死 Turbopack 构建。
