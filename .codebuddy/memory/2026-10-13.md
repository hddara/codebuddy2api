# 2026-10-13

## 流式 SSE 严格兼容修复（分支 fix/sse-strict-compat）

**问题**：Peekaboo（macOS 自动化工具，内用 Swift Tachikoma AI SDK）通过 `peekaboo agent`
调用本网关时每轮报 `finish reason 'other'`；但同一模型在 Cursor / Cline / Claude Code 等
IDE 中流式正常 → 说明是本网关 SSE 帧对**严格客户端**不合规，不是模型问题。

**根因**（抓包实证）：Peekaboo 走 `POST /v1/chat/completions` 的 Chat 直连透传路径
（`normalizeStreamingResponse` → `normalizeStreamToolCalls`），而上游每帧都带：

- 非标准字段：`extra_fields`、`refusal`
- 空占位：`tool_calls: []`、已废弃的 `function_call`（`null` 或 `{name:"",arguments:""}`）
- 首片之后 `function.name = ""`（规范要求省略该键，而非置空）

宽容客户端忽略未知字段；严格客户端把 `name:""` 读成"清空 name"、把 `tool_calls:[]`
读成"重置工具列表"，于是判定响应结构异常。

**修复**（`lib/server/proxy/codebuddy.ts`）：在 Chat 透传路径加 `sanitizeStreamDelta()`
清洗上述字段；tool_call 的 `name` 只在首片保留、后续片删键；新增开关
`CODEBUDDY_SSE_STRICT_COMPAT`（默认开启，置 0 可完全回退原行为）。

**注意**：`reasoning_content` 必须保留——`anthropic.ts` 真实消费它来转 Anthropic thinking。
