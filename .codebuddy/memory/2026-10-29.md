# 2026-10-29

## 11128 的最后一环：`role: "developer"`（已发版 20261029.T01）

用户贴的 DSH 报错日志里，请求体的第一条是 `"role": "developer"`，内容正是
`You are an AI agent powered by DeepSeek Harness.`。这就是前两次修复都没生效的原因：

- `demoteSystemPrompt()` 只认 `role === 'system'`，所以 developer 消息**没被降级**，
  上游看到的是 `system(官方前言) + developer(harness 提示) + user + 131 tools`。
- `rewriteHarnessIdentity()` 只扫 system（T14 后加上 user），developer **完全没扫**，
  所以 `DeepSeek Harness` 原样发出。
- 官方客户端从不发 developer（它的开场永远是 system），这本身就是个非官方形状。

**抓到的实测对照**（同一个 key、同一个 body，只换角色，间隔 20s）：

| 形态                                                                | T14 之前        | T01 之后 |
| ------------------------------------------------------------------- | --------------- | -------- |
| `developer` 携带 `You are an AI agent powered by DeepSeek Harness.` | **400 / 11128** | **200**  |
| 同一段文字放在 `user`                                               | 200             | 200      |

所以触发点既不是工具数量（两个请求都 0 工具），也不是那段文字本身，而是**角色槽位**。

**T01 改动**（`f43acc2`）：`harness-identity.ts` 把 `developer` 与 `system` 归一为
"instruction slot"：降级、注入判定、身份采样、身份改写四处统一处理；降级后 developer
消息被搬进第一条 user，上游只剩 system/user/assistant/tool。

验证：lint / format:check / typecheck / test:coverage（620 测试，行 93.76%）/ build 全过；
镜像 `20261029.T01` 已部署（`--check` = running T01），同一 developer 请求实测 200。

## 工具（tools）到底有没有关系

日志统计（T14 之前的 12 小时）：`toolCount=131` 的请求 1287 次成功、8 次 400；
08:25 那波失败里，一条 **2 条消息 / 0 工具 / 574 字节** 的请求也照样 11128。
所以工具数量不是判据；`toolCount` 只是"这是 DSH 发的"的代理指标，而 DSH 真正与众不同的
是它用 `developer` 承载系统提示。
